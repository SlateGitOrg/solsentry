# Decisions

Rulings made while building solsentry, in the order they came up. Format:
`Ruling: <what> — <why> — <cost if wrong>`.

## Scope and inputs

- Ruling: Analyse the solc *compact* JSON AST (`ast` output selection), not the legacy AST, bytecode or source text — it is the stable, typed representation solc emits for 0.6–0.8, and `typeDescriptions.typeIdentifier` classifies calls without re-implementing type checking — cost if wrong: pre-0.5 contracts (legacy AST only) are unsupported.
- Ruling: Pin exactly two compilers, solc 0.8.26 (default) and 0.7.6 (for `pragma <0.8` fixtures), installed with py-solc-x and verified against the SHA-256 from binaries.soliditylang.org `list.json` for macOS and Linux — two versions cover both arithmetic regimes (wrapping vs checked) and every AST shape the fixtures use; checksums make the compiler a verified input rather than "whatever pip fetched" — cost if wrong: 0.6.x/0.5.x AST differences (e.g. `.value()` call syntax) are untested.
- Ruling: Commit fixture ASTs as self-contained *bundles* (source text + AST + compiler version) plus `fixtures/MANIFEST.json` with source/AST hashes — tests then run offline and can detect a `.sol` edited without regenerating its AST — cost if wrong: ~1 MB of JSON in the repo.
- Ruling: Request only the AST from solc (`outputSelection: {"*": {"": ["ast"]}}`) — no code generation means compiles are fast and deterministic across platforms — cost if wrong: none for analysis; bytecode-level facts are unavailable by design.

## Analysis design

- Ruling: Statement-level CFG nodes (one statement or branch condition per node), not basic blocks — every dataflow fact then maps 1:1 to a source statement and to a reportable location — cost if wrong: more nodes than a block-level CFG (irrelevant at contract sizes).
- Ruling: Inline modifiers into the function CFG, expanding each `_` to the next modifier or the body, with `return` in an inner level resuming after the enclosing placeholder — guards in `onlyOwner`-style modifiers become ordinary dominating nodes, so one dominance query answers "is this protected?" — cost if wrong: a modifier with several `_` duplicates the body (bounded by a 50,000-node cap per function).
- Ruling: Short-circuit `&&`/`||` and the ternary operator are *not* split into CFG edges — the analyses here are path-insensitive within a statement — cost if wrong: a write inside the right operand of `&&` is treated as unconditional.
- Ruling: Taint is a may-analysis over explicit data flow only (no implicit flows), storage tracked per variable root, internal calls via return summaries computed to a fixpoint, parameters of *all* functions labelled `PARAM` (context-insensitive) — simple, predictable, and sound enough for the eight detectors — cost if wrong: internal helpers only ever called with constants are treated as attacker-reachable (possible false positives in integer-overflow).
- Ruling: An *identity check* is a `==`/`!=` with `msg.sender`/`tx.origin` on one side and storage or a non-zero literal address on the other, a boolean expression keyed by the sender that reads storage (`admins[msg.sender]`, `hasRole(R, msg.sender)`), `&&` with any identity conjunct, `||` only if every disjunct is one, or a call to an internal function whose every normal exit passes such a check — this captures Ownable, AccessControl and hand-rolled patterns structurally instead of by modifier name — cost if wrong: polarity is not verified (`if (msg.sender != owner) { privileged }` counts as protected), and `balances[msg.sender] == 0` would count as an identity check.
- Ruling: Reentrancy locks are recognised structurally (a strong write to a storage variable dominated by a check that reads it, directly or inside an internal helper whose exits all pass it) — covers OpenZeppelin 4.x/5.x and Uniswap-V2-style guards without name matching — cost if wrong: transient-storage (`tstore`) locks in assembly are not recognised.
- Ruling: `transfer`/`send`, `staticcall`, and calls to `view`/`pure` external functions are not reentrancy-capable — they forward 2300 gas or compile to STATICCALL — cost if wrong: a future gas-schedule change could make stipend calls re-entrant.
- Ruling: Reentrancy reports writes only to storage variables read somewhere in the program, excluding constants/immutables and lock variables — write-only bookkeeping cannot be observed stale — cost if wrong: a variable read only by off-chain consumers is missed.

## Detector semantics

- Ruling: Every detector has a documented anchor (the reported line): reentrancy → the external call (or the internal call that makes it); tx-origin → the condition; unchecked-call → the call; selfdestruct → the selfdestruct, or the internal-call site in the entry function; delegatecall → the delegatecall; missing-access-control → the write/value-transfer statement or the internal call that performs it; integer-overflow → the arithmetic operation; timestamp-dependence → the `%`/`==` operation — labels and evaluation match on `(file, detector, line)` — cost if wrong: a correct finding anchored on a different line counts as one FP plus one FN.
- Ruling: missing-access-control infers privilege from the code (a variable is privileged iff some identity check reads it) plus a whole-balance-withdrawal rule, rather than guessing from names like `mint`/`setFee` — no false positives from naming conventions and no per-project configuration — cost if wrong: privileged state that is never guarded anywhere is invisible (documented FN class; visible in the holdout results).
- Ruling: integer-overflow only reports operations with an attacker-influenced operand (`PARAM`, `VALUE`, `CALLDATA`, `EXTCALL`) that are not discharged by a syntactic pre-check (a dominating comparison mentioning every non-literal operand) or post-check (a post-dominating comparison relating the result to an operand, i.e. SafeMath) — keeps loop counters and storage-only arithmetic quiet — cost if wrong: no value-range reasoning, so provably safe operations (e.g. `amount - amount*fee/10000`) are reported.
- Ruling: timestamp-dependence reports `%` on timestamp-derived values (randomness) and `==`/`!=` comparisons, not range comparisons — deadlines tolerate validator drift; the SWC examples are about randomness and exact equality — cost if wrong: legitimate calendar arithmetic (`(day + 4) % 7`) is reported as randomness.
- Ruling: Severity HIGH for reentrancy/selfdestruct/delegatecall/access-control/integer, MEDIUM for tx-origin/unchecked-call/timestamp randomness, LOW for timestamp strict equality — follows the SWC registry's typical impact — cost if wrong: only presentation (SARIF level and `--fail-on`).

## Evaluation

- Ruling: Two splits. `dev` (24 pairs) was written first and used while building the detectors; `holdout` (19 pairs + 3 mixed realistic contracts) was written only after the detectors were frozen at commit `1af9f94`, and its first evaluation is reported verbatim — we never tune and report on the same split — cost if wrong: both splits were written by the same person who wrote the detectors, so holdout is "held out" in time, not by a separate author; numbers are an internal-consistency measure, not an industry benchmark.
- Ruling: Holdout labels mark *real vulnerabilities of each detector's category in an auditor's judgement*, including cases outside the detectors' documented reach (an unguarded fee-recipient setter, an upgrade setter) and benign code the detectors are expected to mis-fire on (weekday arithmetic, allow-listed delegatecall) — measuring only what the rules were designed to catch would inflate recall — cost if wrong: labels are one person's judgement.
- Ruling: Several findings of one detector on one line count once — simple set semantics over `(file, detector, line)` — cost if wrong: two distinct bugs on one line are scored as one.

## Hardening

- Ruling: For solc standard-JSON / bare SourceUnit inputs, source text is read only from paths that resolve under `--source-root` (default: the current directory); `..` and absolute paths outside it are rejected — a crafted AST in a pull request must not make the analyzer read arbitrary files and echo them into a SARIF snippet — cost if wrong: ASTs compiled with absolute paths outside the project need `--source-root` (or a bundle) to load.
- Ruling: Malformed AST input is handled at a per-file boundary (`errors.input_boundary`) that converts `KeyError`/`TypeError`/`AttributeError`/`IndexError`/`ValueError`/`RecursionError` into `AstFormatError` (exit 2), instead of a schema validator for every node type — the analyzer reads AST nodes by direct subscript in dozens of places across model, CFG, expression, dataflow and detector code, and a hand-written schema would duplicate the analyzer and drift from it, while the boundary covers every access path by construction (fix round 1, review finding on fuzzed input) — cost if wrong: a genuine analyzer bug triggered by a *valid* AST is reported as "malformed or unsupported AST" rather than a traceback; mitigated by keeping the exception class and message in the error and logging the traceback at `-vv`.
- Ruling: `analyze` continues past a file it cannot load or analyse, prints one error line per bad file, renders the report for the rest, and exits 2 when any file failed even if findings would give exit 1 — an incomplete run must fail CI as an error, and one bad file must not hide verdicts on the others — cost if wrong: a report (SARIF/JSON) that silently lacks the failed file; the failure is visible only on stderr and in the exit code. `eval` stays fail-fast because a partial precision/recall score would be misleading.
