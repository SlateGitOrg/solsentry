# Data

solsentry ships no third-party datasets. Everything under `fixtures/` was written for this
repository and is covered by the repository's MIT license.

| Path | What it is | Source | License |
|---|---|---|---|
| `fixtures/contracts/dev/<detector>/*.sol` | 24 vulnerable/fixed contract pairs (48 files), one directory per detector. Used while the detectors were built. | Written for this repo | MIT |
| `fixtures/contracts/holdout/<detector>/*.sol` | 19 vulnerable/fixed pairs (38 files) written only after the detectors were frozen at commit `1af9f94` | Written for this repo | MIT |
| `fixtures/contracts/holdout/mixed/*.sol` | 3 realistic multi-issue contracts (`CommunityVault`, `LegacyExchange`, `NFTMarket`) with benign code the detectors are expected to mis-fire on | Written for this repo | MIT |
| `fixtures/contracts/unit/*.sol` | 2 feature-coverage contracts for unit tests (0.8 and 0.7 language features) | Written for this repo | MIT |
| `fixtures/ast/**.json` | One *bundle* per `.sol`: source text, solc compact JSON AST, compiler version | Generated by `make fixtures` with the pinned compilers below | MIT |
| `fixtures/MANIFEST.json` | SHA-256 of every source and bundle plus the compiler used | Generated by `make fixtures` | MIT |
| `tests/golden/*` | Expected SARIF for one fixture and expected eval tables for both splits | Generated by solsentry itself, reviewed by hand | MIT |
| `tests/sarif-subset.schema.json` | A trimmed JSON Schema of the SARIF 2.1.0 fields solsentry emits | Hand-written from the OASIS SARIF 2.1.0 specification | MIT |

Labels: each line that a detector *should* report carries an inline `// @expect: <detector-id>`
comment (56 labels in total, `grep -rn "@expect" fixtures/contracts | wc -l`). Fixed variants
carry no labels, so any finding on them is a false positive. Labels in the holdout split reflect
an auditor's judgement of real issues, including ones outside the detectors' documented reach
(see `DECISIONS.md`, "Evaluation").

Size: `du -sh fixtures` reports 2.1 MB, all text.

## Compilers

ASTs were produced by the official solc release binaries, installed with `py-solc-x` and
verified before use against the SHA-256 in binaries.soliditylang.org `list.json`
(pinned in `src/solsentry/compile.py`):

| Version | Used for |
|---|---|
| `0.8.26+commit.8a97fa7a` | every fixture with `pragma solidity >=0.8` (default) |
| `0.7.6+commit.7338295f` | fixtures whose pragma requires `<0.8` (wrapping arithmetic) |

solc is GPL-3.0 licensed; it is downloaded on demand into `.solcx/` (git-ignored) and never
committed or redistributed. Tests and `make check` never run a compiler: they read the committed
ASTs. `make fixtures-verify` recompiles every fixture and checks the committed bundles reproduce
byte-for-byte (needs network on first run to fetch solc).

## Not a benchmark

All fixtures are synthetic and were written alongside the detectors. They are not
SmartBugs, SolidiFI or any public benchmark, and the precision/recall figures computed on them
are an internal-consistency measure, not a comparison with other tools.
